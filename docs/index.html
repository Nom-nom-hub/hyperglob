Find the files you mean.
Not the files that look like them.

Traditional globbing matches strings. hyperglob parses. Ask for the files that actually export a symbol, or actually import a package, and you get an AST-verified answer — evaluated during the crawl, not in a second pass.

The problem

Agents were built to read every file

Ask an agent to change a hook, and it globs, reads a hundred files, and greps for a string. Every step is a guess that a string matcher cannot verify.

✕ Glob + grep + read

  • grep -r "useServerHook" matches comments, strings, and dead code.
  • export const x in a comment looks exactly like an export.
  • Every candidate file is read into memory, then thrown away.
  • Three passes over the tree to answer one question.

✓ hyperglob

  • The parser runs inside the crawl. No second pass.
  • Comments and string literals are not exports. The AST knows.
  • Files are read once, in Rust, and filtered before crossing the boundary.
  • One pass. One allocation. Answer as you walk.

The query language

Selectors that know what a file means

Append selectors to any glob. They compose with AND semantics, stack with ! negations, and all of it is evaluated in Rust during traversal.

:exports("name")

Does this module really export that symbol?

Declarations, export { a as b }, re-exports, and default exports all count. Text in a comment does not.

:imports("pkg")

Does this module depend on that package?

Covers import, require(), dynamic import(), and export … from — including subpaths like react/jsx-runtime.

:contains("text")

Does the file contain this literal?

Searched with memchr inside the traversal. Use :contains(/regex/) or :matches("re") for patterns.

:has-key("a.b.c")

Does this JSON file have that key?

Dotted paths and array indices work: :has-key("deps.0.name").

:size(<100kb)

Filter by file size.

Evaluated at the stat step, so it costs nothing extra. Units: b, kb, mb, gb, kib, mib, gib.

:modified(>2026-10-01)

Filter by last-modified time.

UTC. Accepts YYYY-MM-DD and full ISO timestamps. Operators: <, <=, >, >=, =.

Three surfaces, one engine

Use it however you already work

Node API

Stream entries asynchronously, or batch them synchronously. A pathsOnly fast path skips entry construction entirely.

for await (const e of hyperglob('src/**/*.ts')) {
  console.log(e.relativePath);
}

Scriptable output, real exit codes, and flags for every option. JSON when you need it, plain paths when you don't.

Under the hood

Built for the boring parts, too

Ignores what your repo ignores

.gitignore, .ignore, .agentignore, .git/info/exclude, and the global gitignore — all obeyed natively, down the tree, with correct negation semantics. No manual exclusion lists.

Knows your blast radius

hyperglobDependents() returns every file that imports a given file, directly or transitively — with TS ESM extension mapping, index.* resolution, and bare monorepo specifiers.

Remembers the tree

An optional warm index snapshots the tree and validates it by mtime. Repeat queries answer from memory: 39 ms vs 83 ms at 110k files. The index rebuilds itself the moment anything changes.

Safe by default

Patterns cannot escape the working directory. Symlink cycles terminate. A corrupt native binary is detected and replaced instead of throwing a cryptic loader error. MCP registration is opt-in.
